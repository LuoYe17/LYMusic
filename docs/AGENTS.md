## 写作规则

- **只写当前事实。** 历史留在 commit、PR 与笔记里。正文不写「以前 / 现在 / 不再 / 待实现 / 未来会」这类叙述——状态会腐化，仓库结构与代码本身就是状态。
- **不复述权威来源。** 命令清单在 `package.json`，文案 key 在语言文件，类型在 `src/`——需要时链接过去，不要手抄；手抄的那一份一定会过期。
- **一段一行。** 一个自然段写成一整行（靠编辑器软换行显示），diff 才干净。
- **相对链接。** 链到具体文件（可带小节）；引用历史用 PR 号，不写 commit hash。
- **中文**，术语统一：主进程 / 渲染进程 / 音源 / 决策笔记。
- **层级即详略。** 只讲自己这一层的事，更深的内容链到它的 owner。

## slop 清单（评审时照着挑）

- 复制粘贴的规则：搜一句特征话，保留一个家，其余改成链接。
- 不该出现的历史：正文里讲「曾经是这样，后来改成了……」。
- 实现状态标注：「已实现！」「后续会……」。状态会烂，删掉。
- 手抄清单：把脚本列表、i18n key、目录树又抄了一遍。
- 推理流水账：一步步写「先改了 A，又发现 B」——留下结论，删掉过程。
- 一逗到底的长段：一段塞三条规则还带括号补充，拆开或下沉。
- 强调通胀：满屏加粗与「关键」「务必」，等于没有重点。
- 已交付文档里的提案语气：「应该」「计划」「建议后续」。

## 字数预算

上限清单在 [scripts/doc-budgets.json](../scripts/doc-budgets.json)，`npm run verify:docs` 会拒绝超限，也会拒绝「清单里有、文件却不在」（改名或删除后要同一次改掉清单）。

- 计数方式：**去空白后的字符数**。中文按字算，`wc -w` 对中文没有意义。
- 机器维护的区块（CodeGraph 段、HTML 注释）不计入。
- 预算只覆盖代理会反复改的常备文档；`README.md` 这类产品文档不在清单里。

超限了按顺序处理：

1. **搬迁**：内容属于别的层级就搬过去，原地留一行链接。
2. **压缩**：确实属于这里，但能写得更短。
3. **调高上限**：只有这些字真的需要空间才调，并在 PR 里说明。

上限是护栏，不是压缩目标：低于上限时留约 5% 余量；超限先执行前两步，再谈第三步。
