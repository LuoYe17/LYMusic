# 子系统：国际化

**当前只有简体中文（`zh-CN`）**。多语言已随功能瘦身一并移除（en-US / ja-JP / ko-KR / zh-Hant 在 `chore: slim features — drop sleep timer, intelligence, desktop lyric, multi-lang` 中删除）。代码里保留的 i18n 结构是为了文案集中管理，不是为了将来必须多语言。

> 注意：根 `AGENTS.md` 与 `DEV.md` 里「五门语言同步」的旧说法已经作废；文案规则以本文件为准。

## 结构

- `src/i18n/languages.ts`：语言清单与默认/回退语言（当前都指向 `zh-CN`）。
- `src/i18n/lang/zh-CN/*.ts`：按功能分文件（`common` / `player` / `search` / `settings` / `download` …），每个文件 default 导出一棵对象树。
- `src/i18n/utils.ts`：`import.meta.glob('./lang/**/*.ts')` 自动收集所有语言文件并拼成 messages，**新增语言文件无需登记**。
- `src/i18n/renderer.ts`：渲染进程 `createI18n` 实例（`legacy: false`，配合 `<script setup>` 用 `t()`）。
- `src/i18n/main.ts`：主进程用的极简 i18n（无 vue-i18n 依赖），`locale` 非法时回退默认语言，不崩。

## 规则

- 用户可见文案一律走 i18n，**不硬编码中文字符串**；主进程要显示的文案（托盘菜单等）也要走 `src/i18n/main.ts`。
- 语言切换链：渲染进程 `change-language` → 主进程改 locale + 刷新托盘 + 广播 `language-changed`（见 [desktop-shell](../subsystems/desktop-shell.md)）。
- 文案 key 用 `模块.语义` 命名，别用序号。

## 加一条文案

1. 在对应功能文件里加键，例如 `src/i18n/lang/zh-CN/settings.ts`。
2. 代码里用 `t('settings.xxx')` 消费。
3. 跑 `npm run lint:i18n`（等同 `bun scripts/check_i18n.ts`）。

## 门禁

`scripts/check_i18n.ts` 检查三件事：各语言缺失的键、多余的键、以及**代码里引用了不存在的 key**（会直接报出 `文件:行 -> key`）。它还能通过 `I18N_STRICT=1` 把告警升级为失败。`TARGET_LANGS` 当前为空数组，跨语言 diff 因此跳过——将来真加语言时在这里登记目标语言。
